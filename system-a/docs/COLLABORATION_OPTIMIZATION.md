# A/B 协作设计与本轮验收

目标：在精品创作、调用成本、缓存复用和少操作之间取得可验证的平衡。A/B 独立运行、独立数据，通过采用稿交接；用户主要选择采用结果和提出修改。保持完整目标，不把某一项测试通过等同于整体完成。

本轮基线备份：`.maintenance-backups/collaboration-20260928-010641`。

## 采用的协作结构

```text
你：选择采用结果、提出修改
└─ 项目主控（程序保存正式状态、安排下一步，不额外付费调用“总管”）
   ├─ A 的独立项目库
   │  ├─ 原创：故事节点 × 创作阶段 × 稳定策略 → 持续复用创作会话
   │  │  └─ 本节点的独立复核会话 → 只返修未通过的候选
   │  └─ 小说：同一本来源的改编会话 → 按阅读单元继续
   │     └─ 独立复核会话 → 阅读依据、人物、因果和事件状态
   └─ 通过采用稿文件交接到 B 的独立项目库
      ├─ 电影拍摄版会话 + 独立复核会话
      ├─ 剧集拍摄版会话 + 独立复核会话
      ├─ 快节奏短剧拍摄版会话 + 独立复核会话
      └─ 当前呈现方向 × 场次
         └─ 导演 / 分镜会话 + 本场独立复核会话
```

会话按实际任务首次创建，不预先运行全部分支。相同职责、方向和目标内继续同一会话；换作品、换呈现方向、作者与审查者之间隔离。独立复核指独立上下文和判断，不要求额外购买另一家模型。用户不需要管理这些窗口或重复粘贴背景。

正式依据始终是平台保存的采用稿、来源映射、实体身份、对白和事件状态。会话记录只帮助推理延续，被拒绝的草稿不能自动变成事实。

## 已落地的机制

- [x] 原创任务保存 generationId、策略、批次与候选；恢复复用已完成通道。明确换方案产生新任务意图，但继续相同职责会话。每张故事方向卡只采用一个根节点。
- [x] 原创复核除了评分，还必须逐项给出人物、因果、对白、连续性、覆盖和呈现的依据；已通过且内容与来源不变的候选免于重复审稿。
- [x] 小说、拍摄版、分镜使用独立审查。创作最多两次自动返修，支持局部补丁；不完整的审查报告只补报告，不能触发作者无意义重写。没有进展及时停止。
- [x] 本地结果缓存、并发重复请求合并、精确会话续接及包含删除操作的上下文差异。没有发送给 CLI 的 API 参数不影响 CLI 缓存。
- [x] 立即返修的基稿若精确等于上一条输出，直接绑定该结果；规范化、合并后的不同稿件不冒用此优化。失败恢复时发送完整资料。
- [x] A/B 共用登录目录时通过跨进程队列协调平台调用；两个项目库仍独立。排队可取消，活进程的会话不会因等待太久被另一个任务抢走，死亡进程释放占用。
- [x] 连续差异达到维护条件后，在下一次正常调用内发送状态检查点，不新开会话、不单独追加一次模型总结。CLI 压缩提示要求保存当前资料、规则及最近草稿；正式状态另存数据库。
- [x] 上下文不一致只在原会话内自动重同步一次，两次用量均计入记录；再失败停止。额度、登录、网络和超时不会因此被盲目重试。
- [x] 小说默认按章节阅读单元前进，续写只携带相关人物、容器、持有关系、隐藏内容和必要前情；完整登记册由程序保存。分镜按呈现方向及场次组织；局部修改保留未改镜头并校验承接。
- [x] B 自动推进方式与电影／剧集／短剧方向分别传递，保留旧客户端 single/until_choice 参数兼容；不会把“推进方式”当成“呈现方向”。
- [x] B 可勾选不连续镜头、跨场选择、全选本场、清空并复制文本。已保留镜头允许复制，仍受精修保护。对白来自镜头所属拍摄版，按呈现顺序输出，含预演／倒叙说明；剪贴板受限时显示完整文本。全程不调用模型。
- [x] 桌面与 390px 窄屏保留阅读、采用、局部修改的操作。文字分镜未出图时缩短占位区域，避免竖屏空白挤占正文。

队列仅协调通过这两套平台发出的调用，不接管用户自己运行的桌面会话或其他 CLI。原生供应商前缀缓存仍由服务商管理，续用会话不等于免费，也不保证每次命中。

## 验证边界

这是一套已实现并经过工程、浏览器和小范围真实文字验证的协作方案；“每部作品都达到精品”仍要通过具体剧目的采用率、返工次数、道具连贯性和成片效果衡量。

尚未进行整部长篇、多日连续调用和 CLI 原生自动压缩触发后的真实压力测试。已验证的是数据库恢复、原会话检查点、差异删除及模拟上下文丢失后的有界重同步。超大单次转换若超过配置范围会明确阻止提交，不会悄悄删掉事实来凑上下文。

真实图片、视频及成片美学效果单独验收，不能用文字协作或离线媒体测试代替。CLI 继承现有模型选择与账号登录；媒体仍通过原有费用预览触发。
