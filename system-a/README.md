# SYSTEM A 2.0 · StoryLab 故事决策系统

System A 负责原创或小说改编中的人物、故事、因果、事实和采用剧本。它与 System B 独立运行、独立存储，通过 `SceneExport-v1 / schemaVersion: 4` 文件交接。

## 启动

安装 Python 3.11+。Windows 双击 `start.bat`；macOS 运行 `start.command`；Linux 运行 `./start.sh`。首次启动会创建 `.venv` 并安装固定依赖。

浏览器默认打开 `http://127.0.0.1:8787`。数据保存在本目录的 `data/`。

```bash
python launcher.py --check
python launcher.py --port 8797
python launcher.py --data D:/Studio/system-a
python launcher.py --test
```

## 工作方式

### 原创

AI 先给选题候选。你选择方向后，系统逐级形成故事结构、场景和完整剧本；候选、拒绝稿与采用稿分开保存。事实提案只有采用后才进入正式版本。

### 小说改编

上传 TXT 或粘贴正文后，系统先建立章节索引；所选章节优先深读并改编，不再等待整本小说处理完成。需要全局伏笔与人物关系图时，可单独启动“全书深读”，结果按单元增量保存：

1. 保存原文 SHA-256、稳定章节/分段位置和来源版本。
2. 缓存每个单元的人物、关系、时间线、伏笔、物件、规则、保护事实及改编机会。
3. 原文更新后只重读变化单元，再复查受影响结论。
4. 页面显示已理解的章节覆盖；后台继续区分已载入、已理解和已通过独立审查，不会把载入动作冒充理解完成。
5. 未通过检查的候选可按问题做局部 JSON 补丁并重新独立复核，保留正文、稳定 ID 与来源映射，不重复生成整篇。
6. `/advance` 自动完成无需你决定的分析，停在下一份完整候选。

采用稿导出 SceneExport v4，包含稳定正文/对白 ID、事件状态、人物与观众知识、戏剧作用、证据快照、分析覆盖和版本指纹。B 仍能读取 v1–v3。

## 反馈与持续改进

在“反馈与记忆”中直接指出问题、修改要求或认可范例。明确要求立即用于当前作品；从选稿行为推测的偏好必须确认；跨作品推广必须再次确认。经验可查看来源、修改条件、记录效果、停用和撤销。短剧偏好、本作品人物或剧情事实不会被错误带入无关作品。

## 模型与会话

“服务设置”可选择本地 Codex CLI，复用本机登录；全局设置和角色设置都提供 `GPT-5.6 Sol · High` 快捷预设，并同时设置 600 秒等待上限和 96,000 字符任务资料上限。创作、小说分析和独立审查使用各自持续会话，只同步变化、删除项和当前适用经验。也可配置 OpenAI 兼容、Anthropic 或 Gemini API。演示模式只验证工程流程，不代表真实文字质量。

详细会话设计见 [CLI 接入与会话管理](docs/CODEX_CLI_2026_09_28.md)。完整能力见 [A/B 2.0 完整版本](docs/COMPLETE_VERSION_2026_09_28.md)，交换协议见 [SceneExport v4](docs/SCENE_EXPORT_V4.md)，验证结果见 [测试报告](docs/TEST_REPORT.md)。

## 部署边界

这是单用户本地源码，不是公网多租户服务。保持默认 `127.0.0.1` 监听。项目备份可能包含原稿、角色设定、模型输出与审查证据，请按私人资料保管。
