# 人物、场景、道具表与参考图（bible.md）

参考图让视频模型在每个独立请求里认出同一个人、同一个地方、同一件东西。bible.md 只写看得见的设定，参考图清单由工具生成。

## 格式

```markdown
# 人物
## 林川
- 别名：小林、林医生
- 身份：二十二岁医学院实习生，清瘦，短发，眉眼倔强
- 造型（白大褂）：白大褂，里面浅蓝衬衫，胸前挂实习生工牌
- 造型（便服）：灰色连帽卫衣，牛仔裤，帆布鞋
- 声音：清亮，语速快

# 群演
## 保镖
- 人数：2
- 造型：黑西装，耳麦，寸头

# 场景
## 医院大厅
- 布局：挂号窗口在北墙，旋转门在南侧，中央一排蓝色候诊椅

# 道具
## 急救包
- 别名：红色急救包
- 外观：巴掌大的红色软包，印白色十字
- 持有：护士
```

- 名字就是 ID：剧本、分镜和这里必须一致。别名帮工具认出「林医生」就是「林川」。
- **造型**：第一个是默认造型，写在前面的会先出图。换装在剧本里写「【状态】林川 换上 便服」。
- **身份**只写外貌：年龄感、体型、发型、脸部特征。性格和背景写在大纲里。
- **持有**：开场时道具在谁手里。

## 什么值得单独登记

| 东西 | 怎么处理 |
|---|---|
| 人物的脸、体型、固定发型和服装 | 人物 + 造型 |
| 会被拿起、交出、打开、损坏的东西（武器、手机、信封、钥匙） | 道具 |
| 建筑、房间布局、固定陈设 | 场景 |
| 表情、姿势、出汗、短暂动作 | 不登记，写在画面里 |
| 道具的开合、满空、临时摆放 | 同一个道具，写【状态】或画面 |
| 换装、明显的伤、场景大改造 | 新造型或新状态，按需要出新图 |
| 无名的一群人 | 一个群演条目，写人数和统一造型 |
| 很小、不影响剧情的东西（纱布、杯子） | 不登记，或加「参考图：否」只用文字描述 |

人物和道具分开建：不要把手里的武器画进人物图，也不要因为「拿着 / 空手」做两张人物图。

## 参考图怎么来

运行 `sf.py assets <项目>`，得到 `derived/assets.md`：每张图的保存路径、比例、用在哪些请求，以及一段出图提示词。

- **母图**用文字生成：人物三视图加正面半身特写、场景 45 度俯视全景、道具四视图。
- **子图**（其他造型、夜景、道具的另一个状态）用母图做参考去改，只改变化的部分，这样身份不会漂。
- 图存到提示的路径（`assets/images/<名字>/<造型或时段>.png`），再运行 `sf.py plan`，提示词里的 @图片 就会对上文件，`requests.json` 里会带上路径。

## 人脸政策：先测试，再批量出图

据公开报道，字节系视频模型会拒收看起来像真人照片的人脸参考。用写实风格之前：

1. 先为一个主角出母图。
2. 把它放进一个 4–5 秒的视频请求里，看能不能上传、生成的人像不像这张图。
3. 能用就继续；被拒就改成风格化写实，或者走平台的授权肖像。

结果写进 series.md 的「人脸」一项，例如「风格化（冒烟测试通过 10-05）」。

三视图加特写的版式也是一个起点假设，同样用冒烟测试确认。

## 参考图名额

Seedance 2.0 一个请求最多 9 张图，社区经验是超过 6 张就不稳。工具每个请求最多用 6 张，按这个顺序挑：说话的人、其他在画面里的人、场景、画面里的道具、群演、只被提到的道具。名额外的只用文字描述。所以，主要人物要登记清楚；不重要的小东西不要登记成道具。
