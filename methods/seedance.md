# 生成请求与提示词（Seedance 2.0 / 即梦）

工具已经按模型的写法生成提示词。这份说明解释它为什么这样写，以及拿到视频后怎么判断、怎么修。

## 工具怎么分组请求

- 一个请求 = 同一场里连续的 1–4 个镜头，4–15 整数秒（含少量剪辑余量，剪辑时修掉）。
- 在时间跳转、场景切换、画面里人物换装或受伤处自动切开，免得参考图和画面对不上。
- 每个请求最多 6 张参考图。

## 提示词的结构

```
16:9，<画风>。<地点>，<时间>，<光线>。
@图片1 是<人物>：<这一刻的造型和伤情>。
@图片2 是<场景>：<布局>。

0–4秒，<景别>，<站位>：<看得见的动作>。<人物>：“<台词>”
4–9秒，<景别>：<动作>。画外传来<人物>的声音：“……”

<声音>，无背景音乐，无字幕。
```

为什么这样写：

- **每张图的身份只说一次。** 模型靠 @图片 编号对应参考，重复的长清单只会稀释注意力。
- **按时间分段。** 超过 8 秒的内容用时间段写，模型更容易在对的位置切镜。
- **只写看得见的。** 理由、规则、内部编号、工作状态、给剪辑师的话都不进提示词。
- **心声写成画外音，并注明人物不开口。** 否则模型会让人物对口型。
- **正面描述。** 「她把钥匙放在桌上」比「不要拿着钥匙」可靠。

`derived/<集>/prompts/` 里的文件由工具生成。要改内容，改 script.md、shots.md 或 bible.md 后重新运行 `sf.py plan`。临时手改某个提示词可以，但下次运行会被覆盖，记得把改动落回源文件。

## 提交

`derived/<集>/requests.json` 列出每个请求的秒数、比例、参考图路径（按 @图片 编号排序）和一条现成的 Dreamina 命令。`ready` 为 true 表示参考图都已就位、没有错误。

提交前确认：

- 账号和模型版本可用（`dreamina user_credit`）。
- 参考图路径都存在。
- 同一个请求不要重复提交：先记下返回的 submit_id，用 `dreamina query_result --submit_id …` 取结果。

## 冒烟测试（第一次用一个项目时必做）

挑 3–6 个有代表性的请求：双人对话、道具交接、换装后的第一镜、一个动作镜头。每个生成 2 次，看：

1. 参考图能否上传（人脸政策）。
2. 人物是不是参考图里的人，服装和伤情对不对。
3. 切镜是否大致落在时间段上。
4. 台词是否说对，心声有没有被说出来。
5. 有没有多出来的人、文字或道具。

把结论写进 notes.md，必要时调整 bible.md 的描述或分镜写法，再批量生成。

## 拿到视频后怎么修

| 问题 | 处理 |
|---|---|
| 偶然的坏结果（手指、表情、动作走形） | 同一提示词重抽 |
| 人像不像、服装不对 | 检查参考图和造型描述；必要时重做子图 |
| 一个请求里镜头太多、切乱了 | 在 shots.md 里给中间某镜加 `转场=重置` 拆开，或减少该场镜头 |
| 动作做不出来（打斗、精细手部、多人接触） | 改分镜：拆成单人动作、局部特写和反应镜 |
| 内容被拒 | 不要原样重提；改画面描述或参考图 |
| 连续性断了（道具消失、位置跳） | 用剪辑遮挡（插一个反应镜），或补一个桥接镜头 |

## 模型难点

多人肢体接触、连续打斗、精细手部操作、屏幕或纸上的文字、液体倾倒、人群走动。这些地方要么拆镜头，要么准备多抽几次，要么在剪辑时用反应镜遮挡。
