# StorySystems 3.0 · 剧本与制作工作室

一个本地应用、一个数据库、A/B 两个工作区。呈现转换和版本比较统一由 A 完成，B 使用采用稿进行导演与制作。

**A 原创／小说改编 → 电影／剧集／短剧版本与比较 → 采用剧本 → B 导演分镜 → 基础资产与必要子图 → 生成单元 → 连续情节审片与成组采用 → 制作包。**

## 启动

Windows 双击根目录 `start.bat`。A：`http://127.0.0.1:8787/a/`；B：`http://127.0.0.1:8787/b/`。

原来的 `system-a/start.bat`、`system-b/start.bat` 也会启动同一工作室并打开对应工作区。升级后先关闭旧服务终端，再使用统一入口；新启动器不会自行终止旧服务或任务。

首次使用默认入口，将旧 A/B 的数据库记录、项目、候选、审查、费用、任务及 Codex 会话标识导入根目录 `data/studio.sqlite3`，配置合并到 `data/settings.json`。原数据库和原始素材继续保留，旧素材通过已登记文件路径读取。遇到运行任务或 ID 冲突时停止导入，不覆盖原库。

已有 Python 虚拟环境和依赖记录会复用。依赖缺失时启动器才安装。支持 `python launcher.py --no-install --no-browser`；`--data <目录>` 使用独立数据目录，默认不导入旧库。`--legacy` 仅用于打开旧独立入口。

## 使用

1. 在 A 选择原创或上传整本 TXT；可先只改编选定章节，章节分析继续增量缓存。
2. 在 A 阅读推荐稿，选择呈现方向、局部修改或并排比较版本。不同方向和历史稿分别保存。
3. 点击“进入导演与制作”。首次建立对应方向的 B 制作分支；更新已有分支时显示真实影响，未改动场次保留。
4. B 可选择少数关键场次比较拍法；普通场次使用通过独立复核的推荐分镜自动推进。
5. 人物基础母图使用正常、中性的表情。道具独立，环境为空场景并保留固定布局。笑怒、姿势、拿放、开合和位置默认复用母图；明显服装、伤势、结构等外观变化才补必要子图。
6. 每次图片、视频生成前仍展示费用和缓存。视频返回后标定实际镜头区间，连续情节审片，再查看整段并成组采用。承接使用采用区间末态。
7. 剧情修改从 B 记录建议后回 A，A 的新候选仍需你阅读、采用；B 不额外重写一份剧本。

## Agent、会话与调用

程序管理任务和正式状态。A 创作、小说分析、各方向剧本、独立复核，以及 B 场次导演、独立复核、连续情节审片复用各自职责会话。同一任务续接已有 Codex CLI 会话，同步变化、删除和当前适用经验，不每次重发完整小说或全部 skill。

账号调用队列、数据库任务池、连接并发计数使用公共实现。作者和审查者分别续接；审查者读取来源、候选和依据，不继承作者推理。实际媒体请求与采用记录分别保存；正文或规则更新不自动产生付费媒体返修。

文字模型仍可选择本地 Codex CLI 与 `GPT-5.6 Sol · High` 等现有配置。Dreamina/Seedance 配置、每批费用确认、任务恢复和经验页继续保留。
