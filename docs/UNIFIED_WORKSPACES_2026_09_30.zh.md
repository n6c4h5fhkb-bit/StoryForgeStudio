# A/B 工作室：本轮设计与实现补充

日期：2026-09-30。本文件补充 9 月 29 日的外部评审包：旧包是改动前的历史快照；分工、运行方式和接口以此文件为准。本轮按用户要求不运行测试。

## 流程与边界

```text
一个本地应用、数据库、任务池和账号调用队列
├─ A 剧本工作区
│  ├─ 原创／小说分段理解与改编
│  ├─ 电影、剧集、快节奏短剧版本的创作与比较
│  ├─ 独立情节复核、局部修订、版本采用
│  └─ ScriptPackage-v1 已采用剧本
└─ B 导演与制作工作区
   ├─ 固定 A 的采用版本，不独立重写情节
   ├─ 事件与实际入画资产 → 关键拍法 → 推荐分镜
   ├─ 基础母图／必要子图 → 生成单元与费用预览
   ├─ 实际视频区间 → 连续情节审片 → 成组采用
   ├─ 采用区间及实际末态 → 后续承接／制作包
   └─ 情节修改建议 → A 生成新候选，由用户采用
```

原创／小说改编、影视形态、画幅分别选择。A 每个呈现方向保存独立采用指针；B 每个方向保存独立制作分支。切换不会覆盖历史。已经按目标方向独立复核、采用的小说改编稿，可以直接发布为制作版本，免去一次重复改写。B 的普通场次按推荐导演稿推进；用户只需集中勾选想比较不同拍法的关键场次。

## Agent 与会话

程序作为主控，保存正式事实、任务依赖、费用与人类选择。模型负责创作和审查判断，不能自行扩大工具权限或触发付费媒体。

| 职责 | 会话与上下文 |
| --- | --- |
| A 原创 | structure、story、script 职责续接 |
| A 小说 | 分段分析与选段改编续接，保留范围缓存 |
| A 呈现 | presentation；`script:<方向>` 作用域 |
| 独立文字复核 | reviewer；读取来源、候选及证据，不继承作者推理 |
| B 场次导演 | shots；`shots:<方向>:<场次ID>` 作用域 |
| B 连续审片 | vision；`sequence-review:<方向>:<场次ID>` 作用域 |
| 媒体执行 | 程序提交固定请求，保存远程 ID、文件和恢复记录 |

独立 agent 是独立职责与会话，不是每次调用新开聊天。CodexSessions、账号队列、配置、任务持久化和子进程管理使用公共实现；旧会话 ID 与检查点保留。同职责续接时同步变化、撤销、当前适用经验和少量范例。`shortdrama-director` 的资产卡按需读取并带版本指纹，不把整份 skill 每轮重发；内容仅作为资产设计参考数据。

## 采用版本与协议

A 的 `script_version` 保存方向、完整正文、事件状态、来源映射、独立审查、故事事实修改确认、经验版本与原稿快照。`ScriptPackage-v1 / schemaVersion: 1` 包含采用版本 ID、来源作品、方向、`scenes`、`storyDocument`、稳定正文和对白 ID、初始与事件前后状态、观看顺序、映射、指纹、演示标记和复核依据，同时保留 SceneExport v4 的阅读范围、事实、知情、戏剧作用与证据。

B 保存 `adopted_script` 与 `activeScriptId`，绑定 A 的 `sourceScriptVersionId`；原 `shooting_script` 与历史素材保留。更新前预览变化场次、保留场次及受影响镜头/媒体；采用时再次校验依据。场次签名包含相关身份、事件状态、容纳和持有、观看顺序，不把无关世界状态纳入局部失效。

全书索引和后台分析进度保存在来源证据，不反复发送给呈现 agent，也不单独让已采用章节稿失效。正文或相关故事事实变化才改变创作依据。旧 SceneExport 1–4 继续可读；统一入口将旧交接稿带回 A 补全呈现与连续性，不把缺失状态伪装为完成。

## “干净图”：正常基础状态

“干净”不是洗掉故事要求的伤、污渍或服装，而是母图不用特殊笑怒表情和场景动作。

| 类型 | 母图 | 何时补子图 |
| --- | --- | --- |
| 人物 | 同一身份和基础服装，中性表情、稳定姿势、空手；2×2 头部正侧、身体正背 | 实际入画且服装、发型、伤势等明显外观变化需视觉锚定 |
| 道具 | 独立本体、正侧背及斜俯视，无持有者和手 | 必要的结构、材质、损坏变化 |
| 场景 | 16:9 高角度全景，空场，保留建筑与固定家具 | 必要布局或环境外观变化 |

笑怒、姿势、位置、持有、交接、包含、开合和显隐仍记录为事件状态，默认复用母图；状态记录并不要求新图。对开合、损坏、内容物等影响观看的道具状态，素材页可在费用预览后按需补状态图，提示词只写物体的物理变化，不带入持有者和位置。子图引用实际直属上级图，仅描述外观差异与保持项。参考记录真实文件、身份哈希、职责、控制范围、排除继承项和人工观察依据。身份图不能证明动作已完成，缺图只阻塞依赖它的任务；参考职责不能保证生成模型绝对遵守。

## 连续情节、视频与成本

文字复核按事件、场次和相邻镜头组检查因果、道具状态、观众知情与信息交付。单镜仅做解码、画幅、时长等基础检测。每镜可声明 `eventPhase`、`endEventPhase`；拆镜后前镜切点末态必须接下一镜起态。动作前的反应镜不能提前标整个动作完成。实质中间状态需要在 A 细分事件。

一个生成单元可容纳连续多个镜头。单元内部承接纳入同一请求；外部强承接等待上游真实采用。时长、图片数量和能力限制读取实际配置，不猜测 Seedance 能力。媒体调用继续先预览已知费用与缓存。

视频返回后保留原文件，并按实际画面标定每镜采用区间。连续审片在区间内抽取真实时间点，保留帧 ID、时间和哈希，结合前后情节与计划状态检查整段。当前是采样视觉审查：缺图、观察不足、模型不可用、未听检声音或未观察的完整动作保持未知。它不能代替人工观看完整音画。

成组采用需用户查看整段，给出观察依据，确认各切点所需末态或填写不同的实际末态。各镜记录一起提交；替换固定采用素材需明确允许。后续承接使用采用区间末态及证据帧，不能用原视频最后一帧。换视频或调整区间只沿实际强依赖使相关结果失效，原文件和无关结果保留。制作包包括采用剧本、播放顺序、素材、媒体、采用区间与版本清单。

## 界面、接口与数据

统一地址 `/a/`、`/b/`。根接口 `POST /api/handoff` 处理 A→B；A 新增 `/scripts` 下的生成、比较、采用、制作包；B 新增采用稿导入/预览、`/change-requests`、`/scenes/{id}/sequence-review`、`/generation-tasks/{id}/adopt`。A 优先显示完整剧本和比较；B 优先显示采用稿、分镜、实际素材与生成单元。B 的情节建议返回 A，仍需用户采用新版本。

修改前备份在 `.maintenance-backups/unified-workspaces-20260929-231235`。默认首次启动将两个旧库事务式导入根目录 `data/studio.sqlite3`，原库与媒体不移动；旧任务仍在运行或 ID 冲突时停止导入。配置合并到根目录 `data/settings.json`。

本轮只做 Python/JavaScript 语法和静态结构、接口衔接核对；没有运行项目测试、启动迁移、浏览器走查、真实文字模型或图片视频调用。因此不宣称本次重构已通过工程、文字或媒体质量验收。旧版本的测试记录也不能替代本次运行验收。
