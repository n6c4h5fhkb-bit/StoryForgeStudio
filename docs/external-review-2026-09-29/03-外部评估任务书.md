# 外部评估任务书与建议交付要求

## 1. 请评估的方案

评估当前两个本地 AI 创作平台：A 负责原创和小说改编，B 负责二次影视化转换、导演分镜、资产、生成、审片和制作包。请以本包详细文档与代码索引为事实依据，区别已实现、静态风险、未完成能力和未验证效果。

用户重点是精品质量与调用费用平衡，愿意多轮选择和局部修改，希望 AI 主动准备下一项结果，避免复杂操作。两条业务路线都要支持：原创高质量作品；小说改编为节奏快、有表演和对白的推文短剧。视频常用 Seedance 2.0 Fast，但不能用固定镜头模板牺牲质量。

## 2. 不应改变的产品要求

- A/B 独立运行、独立存储，用采用故事文件交接。
- B 必须保留完整二次转换阶段，不能将 A 原稿直接跳到分镜。
- 来源路线、呈现方向和画幅分别选择。
- 上传全本后，可以只处理前几章；专项全书深读另行触发。
- 不要求开头设置固定时长，不硬规定每集分钟数、镜头数或反转频率。
- 用户以阅读、比较、采用和自然语言意见为主，内部分析节点后台处理。
- 候选与正式采用分离；已采用内容和历史不被无声覆盖。
- 作者与独立审查隔离；正式事实由数据库版本管理。
- 同职责会话尽量续接，增量同步，重视平台缓存和供应商缓存，但不承诺固定命中。
- 付费媒体先预览并确认；失败不自动重提；不新增媒体累计预算帽。
- 未看过的媒体、缺证据的动作、不可用的检测器都不能算通过。
- 跨作品学习需明确确认，短剧偏好不能自动污染电影，项目事实不能带入新作品。

## 3. 必须回答的问题

### 产品流程与创作质量

1. 当前流程在哪些地方选择过多，哪些地方又自动采用过早？请提出不增加用户操作的修改。
2. 小说选段改编是否能保持原作主线、人物动机、关键物件和前后承接？未读后文如何表达不确定？
3. 电影与快节奏短剧的改编如何验证实际差异，避免只是标签、镜长和措辞不同？
4. 关键场次的启发式选择有什么失败情况？需要语义导演判断还是更简单的改进？
5. 对白删并、心理外化、场次重排如何保留信息与戏剧作用？

### Agent 控制与会话成本

6. 程序主控是否足够？若增加模型主控，请说明它比程序状态机多解决了什么，增加多少上下文、费用和错误面。
7. 哪些职责必须独立上下文，哪些可续用同一会话，哪些可以由程序完成？请给出可执行会话树。
8. 同一作者和同一审查者持久会话会有什么污染／锚定风险？如何控制又保留缓存？
9. scope、角色、模型、方向、目标、检查点和增量删除的划分是否合理？
10. 首稿、两轮修复、报告修复和重同步是否造成过多调用？请给出有依据的成本预算。

### 数据、资产和依赖

11. SceneExport v4 是否足够表达事实、知情、误信、来源、事件和播放顺序？哪些字段缺失或语义模糊？
12. B 的多方向稿历史如何升级为真正独立的制作分支，哪些身份资产可以共享？
13. 道具资产漏提、闭盒／开盒、交接、容纳、服装和伤势如何从原文到视频统一？
14. 参考图如何控制身份，又避免继承旧背景、姿势和持有物？
15. 高层候选复用、审查缓存、媒体缓存和采用状态如何保持依据一致？经验撤销和原文更新有没有旁路？
16. 运行中依据变化，返回结果如何成为旧版本候选而不冒充新版本有效结果？

### 恢复、媒体与经验

17. 已确认的恢复方法嵌套缺陷，以及其他未覆盖的入口问题，如何通过路由级测试防止复发？
18. 网络断在提交与保存远端 ID 之间时如何核对，如何证明不会盲目重提或重复计费？
19. 真实视频采用区间、末态、抽帧、动作和音频听检还缺什么？哪些必须人工？
20. 经验规则如何从反馈、行为信号形成，经确认后应用、独立验证、撤销和跨 A/B 同步？
21. 当前经验的等值条件筛选是否足够，规则冲突和截取上限如何处理？
22. 如何在低成本真实试跑里证明重复错误减少，而非只统计“系统记住了规则”？

## 4. 每项问题的交付模板

| 字段 | 要求 |
|---|---|
| 编号与优先级 | P0 阻止错误付费／数据污染；P1 核心流程和事实错误；P2 质量／成本／体验；P3 扩展性。按实际影响评级 |
| 类型 | 已复现 bug／静态风险／产品缺口／效果未验证，不能混用 |
| 证据 | 文件＋函数＋输入／状态；纯文档推测明确写出 |
| 触发与结果 | 用户做什么，系统当前怎么走，为什么不满足目标 |
| 方案 | 主控规则、Agent 分工、数据模型、接口和 UI 的具体变化 |
| 采用／缓存影响 | 哪些指纹更新，哪些已采用内容保留，哪些后续失效 |
| 费用与操作 | 增减调用和用户选择，不能只说“更智能” |
| 迁移与失败保护 | 旧项目、断点、未知状态、回滚与并发 |
| 验收 | 至少一个失败复现、修复后正例和合理例外／无关场景 |

## 5. 最终建议应包含

1. 当前方案整体判断：适合什么规模和使用方式，成熟度的证据与边界。
2. 目标架构图、完整用户流程、主控状态图和职责会话树。
3. 每个独立 Agent 的输入、输出、正式依据、禁止越权、续接／切换和审查关系。
4. 数据与版本模型、真正制作分支、事件／知识／参考／采用依赖图。
5. 缓存键和撤销／失效矩阵，以及运行中变化处理。
6. 反馈学习闭环、跨平台经验同步、回归案例和效果指标。
7. 最小用户操作路径，桌面和窄屏阅读方案。
8. 完整验收清单、真实试跑成本、缺陷优先级和实施依赖。

用户要求的是完整目标版本设计。请先给完整方案，不要只交付“先做第一步”；工程实施可以有依赖顺序，但最终范围要明确。也不要单纯增加 Agent 数量、把每条流程再拆成用户点击，或用统一大 Prompt 代替数据和状态治理。

## 6. 可直接复制给外部 AI 的提示词

```text
请作为独立产品与 AI 工程架构评审者，深入评估我提供的 A/B 创作平台文档。

我的目标：A 做原创精品／小说改编故事，B 在采用故事上再次做电影／剧集／快节奏短剧转换，再完成导演分镜、道具和角色资产、图片视频制作、审片和制作包。小说推文也是有表演和对白的短剧，视频常用 Seedance 2.0 Fast。精品质量、调用费用和少操作同时重要。

请先区分当前代码实现、此前产品目标和真实验收证据。阅读 02 的全部设计、03 的评估要求、04/05 的源码索引和 06 的场景。索引不包含完整源码；无法由现有材料确认的地方请标注需代码或试跑，不要编造。

重点检查：
1. 程序主控是否合理，作者／方向转换／场次导演／独立审查／媒体执行应如何分工。
2. 同职责持久会话、scope、增量删除、上一输出绑定、检查点、取消恢复和共享调用队列是否平衡缓存与独立性。
3. 上传全本但只改编前几章的路径，以及长文、续写、前章更新和理解覆盖的真实性。
4. B 完整二次影视化；电影与短剧实际呈现差异；单 activeShootingId 与真正制作分支的缺口。
5. 从原文到拍摄稿、事件、素材、分镜、真实参考和视频采用区间的连续性，尤其道具开合、交接、包含、服装和伤势。
6. 高层候选复用可能绕过经验变更、规则撤销、源分析变化的风险。
7. 媒体恢复入口的已确认方法嵌套缺陷，以及费用、未知提交状态、下载恢复和运行中依据变化。
8. 自我改进是否真正闭环，行为信号提炼、规则适用／例外、独立验证、跨 A/B 同步和撤销还有什么缺口。
9. 真实媒体检查与工程测试的区别，缺检测器／未观察保持未知。

给我完整目标版本方案，不只列阶段口号。输出：整体判断、当前问题表、完整用户流程、Agent 会话树、主控状态／权限、每个 Agent 输入输出、数据版本和缓存依赖、媒体恢复、经验学习、最少操作界面、成本与验收。每项优化写具体证据、收益、费用、迁移和反例。

不要假设更多 Agent 就更好；不要删掉必要 B 转换或独立审查；不要固定时长／镜数／反转频率；不要把全部分析节点交给我手动操作；不要自动付费重试或增加媒体累计预算帽；不要把演示／结构测试通过说成真实成片精品。
```
