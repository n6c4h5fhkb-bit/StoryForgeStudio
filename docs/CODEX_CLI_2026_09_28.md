# A/B 本地 Codex CLI 接入

A、B 的创作、改编、分镜和独立复核均可选择 `codex_cli`。两套平台各自保存项目和调用记录，通过本机 Codex 登录进行推理。现有 API 接口仍可按角色配置。

## 本机使用

本机两套数据目录已选择本地 CLI，默认继承 Codex 的模型和推理强度，单次等待上限 600 秒，A/B 共用登录目录的调用队列并发为 1。设置页可检查安装与登录状态，也可以为不同创作任务单独选择模型。

- A：`http://127.0.0.1:8787`
- B：`http://127.0.0.1:8788`
- CLI：已更新至 `0.157.1`。A/B 使用 `codex --no-daemon exec`，避免管理员终端的共享后台服务限制。
- A/B 的全局设置和角色独立设置都提供 `GPT-5.6 Sol · High（精品质量）` 快捷预设；采用后保存为模型 `gpt-5.6-sol`、推理强度 `high`、600 秒等待上限与 96,000 字符任务资料上限，也可继续分别修改。
- 模型名、推理强度留空时继承本机 `config.toml` 对应值；更换模型后使用该模型独立的任务会话。
- CLI 与桌面应用通常共享同一 `CODEX_HOME` 下的登录信息。若检测不到登录，先在普通终端运行 `codex login status`，核对环境目录和系统凭据访问权限，确需登录时才运行 `codex login`。

新建空数据目录仍默认离线演示，不自动提交真实推理。切换文字模型不会开启图片、视频生成。

## 会话树

```text
一个作品
├─ 项目主控：采用版本、事实、任务进度、会话索引（程序管理）
├─ A 故事
│  ├─ 小说改编会话：同一本小说持续复用
│  ├─ 原创创作会话：按故事节点及候选通道复用
│  └─ 独立复核会话：与创作分开，本任务后续复核继续复用
└─ B 制作
   ├─ 电影拍摄版会话＋电影版复核会话
   ├─ 剧集拍摄版会话＋剧集版复核会话
   ├─ 快节奏短剧拍摄版会话＋短剧版复核会话
   └─ 按呈现方向、场次划分
      ├─ 第一场导演与分镜会话＋独立复核会话
      └─ 第二场导演与分镜会话＋独立复核会话
```

主控没有额外调用一个模型“总管”。已有 `/advance` 根据平台保存的项目状态安排工作，用户仍主要负责采用、选择和提出修改。

这些是平台内部的 CLI 会话标识，按需首次创建；用户不需要打开许多聊天窗口、复制提示词或手动选择会话。电影、剧集、短剧也不会全部预先运行，只启动实际选择的路线。A 到 B 只交接采用稿及制作依据，不复制 A 的全部聊天记录。

## 如何省重复上下文

1. 完全相同、依赖版本未变化的请求优先使用平台结果缓存，不启动 CLI。
2. 首次任务发送必要的来源、任务规则和当前状态；不会把整本小说或整个制作项目无差别传给每个任务。
3. 同一任务按明确的 CLI 会话 ID 续接，不使用 `--last`。后续优先发送 JSON Patch 差异，包含修改和删除；长数组的局部变化也会比较差异长度。
4. 大范围替换适合完整资料时，在同一会话发送当前快照。取消、中断或上下文不一致后的恢复，也优先在原会话重新同步，而非随意开新会话。
5. 独立复核有自己的会话，接收来源和候选；不会继承作者会话中的自我评价。返修后的复核持续复用该复核会话。
6. 平台重启后从数据库恢复会话索引。CLI 更新会使版本相关的结果缓存重新校验，但不因此重新创建任务会话。异常退出遗留的占用会检查原进程是否仍在运行。
7. 创作返修优先返回局部 JSON Patch。程序合并修改、检查完整候选，再送独立审查；每个目标仍最多两轮自动修复。一次列出同类参考状态问题，避免每次只发现一个错误就整篇重写。
8. 分镜结构示例去除随机创建标识和数据库元数据；相同输入的重试可命中原结果。兼容的协议措辞升级迁移旧会话索引及结果缓存，不因文字澄清丢掉历史。

平台的已采用版本、对白 ID、事件状态和资产台账始终是正式依据。历史聊天、被拒绝的草稿、旧道具状态不能自动成为事实。会话自动压缩时要求保留当前任务资料；异常结果不会跳过现有结构与语义复核。

不同作品、呈现方向、创作与复核之间隔离。取消/超时会停止 CLI 及其子进程，并释放任务占用；重试不自动改走其他供应商。

## 用量与费用

“调用与费用”显示是否续用会话、本次发送字符、实际输入/输出 token、供应商缓存 token；“查看创作会话”可检查会话记录。只有记录丢失或需要修复时才手动重建。

平台结果缓存与供应商前缀缓存是两回事。续接会话有利于复用已有前缀，但不能保证供应商缓存命中或保留时长。记录以 CLI 实际返回值为准。

续接也不是零上下文成本：历史仍在模型上下文中，达到上限时由 CLI 压缩。因此按作品、职责、方向和场次控制会话范围；纯结构提取、引用映射和缓存判断由程序完成，不额外发起模型调用。压缩后的事实依据仍是平台保存的采用稿，必要时在原会话重新同步。

Codex `0.157.1` 在续接时返回会话累计 token。本实现扣除上次累计值，按本轮增量统计；累计原值同时留作核对。CLI 按账号额度或服务商结算，金额未知，不标成免费，不混入 API 美元金额合计，也不虚构订阅账户的 token 单价。

`temperature`、API `maxTokens` 和 API 请求扩展不用于 CLI。CLI 使用本机或按角色选择的推理强度、任务资料上限和执行超时。自定义 Codex 服务商配置会明确提示；此适配使用官方 Codex 登录，其他端点可使用原有 API 适配。

## 本轮协作优化

原创生成保存任务意图和策略，取消恢复不重抽候选；独立复核按真实目标节点分会话。作者最多两次局部修复，审查报告不完整时只补报告。两套平台通过账号目录内的跨进程队列协调推理，项目数据仍各自保存。

长差异链在下一次正常调用内发送完整检查点，不额外调用总结模型。上下文不一致在同一会话最多重同步一次；立即返修若精确使用上一条完整输出，可以绑定该结果而不重发全文。重同步失败、额度和登录错误不会无限重试。原生自动压缩的长期真实压力测试尚未进行。

B 阅读工作台新增“全选本场 / 复制已选分镜 / 清空勾选”，支持跨场与不连续选择，允许复制锁定镜头，按呈现顺序输出所属拍摄版的对白；不调用模型。自动推进参数与影视方向分开，保留旧参数兼容。

完整设计、会话树、证据和边界见 [协作设计与验收](COLLABORATION_OPTIMIZATION.md)。

## 实现与运维

- `app/codex_cli.py`：执行适配、会话占用、差异资料、结构化结果和累计用量处理。
- `app/call_queue.py`：共享登录目录下的跨进程队列、可取消排队和死亡进程清理。
- `app/process_tree.py`：Windows 子进程组，取消、超时和服务退出时清理调用进程。
- `app/llm.py`：角色调用、结果缓存、去重、费用记录；API 行为保留。
- `static/codex-ui.js`：连接设置、诊断和会话查看。
- A/B 各有一份模块，无跨目录 Python 导入。项目备份恢复不会复用原项目的 CLI 会话标识。

执行使用固定参数和 UTF-8 标准输入，故事文本不拼接到 shell 命令。推理进程使用只读权限，关闭 shell、媒体生成、浏览器、插件和自主委派工具；不加载用户的通用项目指令。采用专用创作基础提示，减少无关编码上下文。登录信息仍由 Codex 管理，不复制到平台设置或项目导出。

验证脚本位于根目录 `tools/verify_codex_cli.py`、`tools/verify_codex_workflow.py`、`tools/verify_codex_ui.cjs`。前两个会发起少量真实文字推理，只写 `.validation` 临时项目；浏览器检查使用隔离服务器，不调用付费媒体。真实图片、视频和最终成片效果仍需另做验证。

官方依据：[非交互命令](https://learn.chatgpt.com/docs/developer-commands#codex-exec)、[登录凭据存储](https://learn.chatgpt.com/docs/auth#credential-storage)、[配置项](https://learn.chatgpt.com/docs/config-file/config-reference#configtoml)。

## 真实试跑发现的修正

分镜引用如果把素材 ID 放进 entityId，只有平台现有映射能唯一定位同一故事实体时才自动规范化，并保存映射记录；未知或歧义引用仍阻塞。每镜灯光的物理参数与场级完全一致时，镜头措辞存入 lightingDetail，正式灯光继承场级，避免仅因文字不同触发整篇返修；真实光位变化仍会拦截。

模型给出的短镜头编号保留为 draftShotId，镜头组中的 shotIds 在审查前映射为实际稳定 ID；引用不存在或含糊的镜头会被拦截。这修复了真实试跑中“分组仍引用旧编号”的问题。

本轮最终工程验证：A 全量 153 项、B 全量 208 项通过。桌面与 390px 窄屏界面、分镜勾选复制、从新建项目开始的自动推进与局部精修、交接及完整离线制作流程通过。

真实文字试跑：A 小说改编与独立复核通过；B 同一原文的电影版、快节奏短剧版及各自复核通过。B 分镜最初因接口标注失败，修复后在原分镜会话中完成两轮局部补丁、独立复核与采用；补丁输出分别为 169、83 token。保留首次失败和后续恢复两份报告，不把工程校验当作成片质量保证。

小型缓存试跑中，第二轮沿用同一 CLI 会话，实际输入 4850 token，其中 4480 为供应商缓存；发送内容由 1022 字符降至 290 字符，第三次相同请求直接命中平台缓存。该结果是一次实测，不承诺其他任务的命中率。图片、视频与成片效果本轮没有做真实生成验证。
