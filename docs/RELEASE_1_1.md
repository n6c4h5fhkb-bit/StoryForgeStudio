# 创作工作台 1.1 · 2026-09-22

本轮已把阅读与选择工作台接入两套独立应用。默认入口使用真实项目、后台任务、候选、版本和导出，不再依赖单独的展示页面。原高级工作台仍可进入。

## 日常使用

1. A 输入故事种子，B 输入剧本或导入 A 的 SceneExport。
2. 点击当前作品右侧的继续按钮。系统根据已采用内容准备下一轮方案；已有有效候选时直接展示。
3. 阅读方案，选择“采用并继续”“仅采用”或填写拒绝原因。AI 不会代替你采用创意方案。
4. 需要精修时，A 在当前场景写一句修改要求；B 勾选具体镜头后写要求。新结果仍先供选择。
5. 通读、查看旧版本，或导出可以离线打开、打印为 PDF 的阅读版 HTML。

可按作品保存字号、纸张/夜间模式、专注阅读、连续阅读和精修输入草稿。任务完成后更新作品；刷新页面会重新接上正在运行的任务。

## 质量与费用

- A 探索方向默认三个候选；正文填充、润色默认一个，风格变化默认两个。高级接口可显式指定 1–5 个。候选数量减少不等于取消内容门禁。
- A 写对白时带入本场正文、相邻场景和相关时间点的人物认知；最低正文结构、对白角色引用与版本依赖均有校验。
- B 拆场、改编、资产、导演、镜头分别使用 normalizer、treatment、assets、direction、shots 角色。通过“模型分工”配置；旧 direction 配置可兼容未独立配置的 treatment/shots。
- 应用缓存、供应商缓存和真实模型调用分开记录。应用缓存命中没有新增模型费用；缺少价格或用量的记录显示估算。
- 重复操作使用持久幂等键；相同缓存请求合并执行。供应商并发限制在每个服务进程内生效。
- 更换模型或地址后需要重新确认价格。请求扩展不能覆盖已经预留预算的模型、消息或输出上限。
- 新创意候选保持新采样。B 拒绝原因与旧方案进入后续请求，避免再次返回同一被拒缓存。

## 版本保护与交接

B 局部精修保持镜头 ID、未选中的镜头、锁定镜头、人工字段和未受影响的媒体。提案采纳前复核生成时依赖，防止旧方案覆盖新修改。场景时长或导演时长与镜头节奏不兼容时，提前引导调整并保留原值，不提交模型。局部精修目前保留原镜头数与时长；整场插镜、删镜和结构重排不属于这个精修入口。

SceneExport v2 增加正文、导演约束和语义指纹、复合源版本和局部认知信息。B 只使相关场景及依赖失效；相同来源重复导入不会覆盖 B 已做的改编。源正文更新会保留旧呈现历史并显示最新原稿。有序动作和对白、角色名在交接和阅读导出中保持。

- 测试使用隔离数据和演示模型；没有修改真实项目或产生付费模型调用。真实服务商协议由模拟响应回归覆盖，尚未用你的付费账号做实测，精品内容质量仍需真实作品验收。
- 本轮仍是单用户本地工作站版本。A/B 各自保存配置与预算，未增加跨平台中央账户额度服务。

复跑后端：在各系统目录使用 `.venv/Scripts/python.exe -m pytest -q -p no:cacheprovider`，并把 `STUDIO_DATA`、`--basetemp` 指向独立测试目录。跨平台验证运行 `python tools/validate_handoff.py`。浏览器验证见 `tools/verify_reader.cjs`，需额外可用的 Playwright 和 Edge。

现有用户关闭旧后台后，重新双击 `system-a/start.bat` 或 `system-b/start.bat`，刷新页面即可进入新工作台。源码备份位于 `.maintenance-backups/before-maturity-20260922-211722.zip`；不包含运行数据库或密钥。
