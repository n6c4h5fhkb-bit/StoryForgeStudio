# A / B 精品创作平台：流程、调用与缓存审查

后续实现说明：这份文档保留最初审查记录；用户随后授权优化，1.1 已实现创作推进、阅读工作台、局部精修、版本保护及调用缓存改造。当前可用范围与验证结果以 [1.1 发布说明](RELEASE_1_1.md) 为准，下文的旧缺陷状态与测试数属于改造前基线。

日期：2026-09-22。依据：现有源码、原始设计、离线回归、局部 Mock 复现，以及官方 API 缓存文档。

这是审查与下一版设计，文中“建议”不代表已经实现。本轮未修改业务代码、真实项目或服务配置，未调用收费生成服务。

## 1. 产品定位与取舍

用户明确的目标：两套独立平台；A 创作精品剧本，B 将剧本转为精品分镜；AI 主动推进和提出方案，人选择结果；通过多轮打磨达成质量，流程复杂度适中，质量与费用平衡。

建议保留两套独立应用和各自的数据，用版本化 SceneExport 交接。两边采用一致的调用、任务、计费规范，但第一阶段不增加强依赖的公共服务。

衡量单位应是“每个被采用并保留下来的剧本段落/场景/镜头的成本”，而非单次调用单价。一次更好的故事选择，可能比节省几次文字推理更能减少后续返工。

产品主流程遵循四条原则：

1. **AI 负责推进，人负责品味与取舍。** 人看具体作品、差异和效果，不维护中间字段。
2. **在高影响的分岔处提供候选，在确定方向后集中打磨。** 不对每个节点机械生成三到五套完整内容。
3. **满意的内容逐步保留，不满意的内容可以局部重做。** 每次改动都能说明影响范围和恢复方式。
4. **用完整作品检验局部质量。** 单场好看不等于全片好看，单张漂亮不等于分镜成立。

底层可以保留契约、事实、版本、依赖、任务等复杂能力；默认界面应围绕创作结果组织，技术详情折叠到高级视图。

### 阅读与使用体验是产品主流程的一部分

阅读质量决定用户能否判断作品，操作负担决定用户是否愿意继续打磨。默认界面先提供完整作品，再在需要选择的地方展开候选、依据和操作，避免把工作台变成等待处理的字段列表。

| 使用情境 | 默认呈现 | 按需展开 |
|---|---|---|
| A 阅读剧本 | 正文占主要区域；场景标题、动作与人物台词有清晰层次；可从开头连续读到结尾，未完成处用明确标记的摘要接续 | 场次导航、批注、候选、局部差异、契约与事实依据 |
| A 选择与精修 | 选中一场或一句话，输入修改方向；先读修改后的完整段落，再看少量关键变化 | 原版/新版并排比较、逐项采纳、其他候选及具体审查证据 |
| B 阅读分镜 | 按场、按镜连续排列图板；每镜的画面、台词/声音和时长同屏可见，镜号与场号稳定 | 大图、镜头参数、资产引用、连续性依据、原剧本对应段落 |
| B 局部比较 | 对变化镜头保留前后镜作为阅读上下文，支持原版/新版连续观看 | 单镜大图比较、调度与转场细节、渲染参数 |
| AI 正在工作 | 当前正式作品仍可阅读；在固定位置显示正在处理哪场、已完成什么、下一次需要选择什么 | 任务详情、费用和错误原因；不以内部日志替代状态说明 |

候选卡展示的是**信息差**：这一版改变什么、带来什么效果、牺牲什么，以及一段能直接判断的作品。共同背景只显示一次，不让用户重复读三份相同设定；不靠堆评分、标签和解释制造内容充足的感觉。A 优先比较人物选择、台词和情绪效果，B 优先比较实际镜头顺序与画面表现。

界面应保留阅读位置、选中场景、展开状态和字号。切换候选或查看任务后回到原处；后台生成完成时提示“新版本可看”，不自动替换正在阅读的内容，也不把页面跳回顶部。采纳引起内容移动时，尽量锚定到同一场或同一镜，并保留回到旧版的位置。

后台状态用清楚的文字区分“排队中、生成中、检查中、待你选择、已保存、失败、已暂停”。有可靠进度才显示百分比；失败说明保留了哪些结果、重试会处理哪部分及是否可能再次产生费用。长任务允许继续阅读、暂停后续步骤和离开页面，回来能看到真实状态。

用户不必编辑 JSON、填写 Canon ID 或理解契约字段。约束、人物设定、时长和修改范围用自然语言、简洁表单与可视选择表达；技术详情供高级用户查看。常用动作采用稳定名称和位置：采用、只采用选中改动、再给一版、保留原版、撤销。拒绝原因可以一句话表达，并区分本次、本场和全项目的适用范围；不要每次操作都要求填写说明。

桌面上以作品为主、导航和选择面板为辅，支持收起侧栏进入专注阅读。窄屏改为单列与抽屉式面板，避免把三栏挤成窄条，也不要求横向拖动才能读完整台词。B 根据空间显示一至三列图板，每张画面保持选定画幅，台词与时长不藏在仅悬停可见的区域；大图模式仍可顺序翻镜。

中文排版建议从正文 17–18 px、行高约 1.7–1.9、每行约 34–42 个汉字起步，按真实剧本阅读测试调整；窄屏正文保持易读尺寸，提供 16/18/20/22 px 等可选字号并记住偏好。场景、动作、角色名、对白使用留白和少量字重区分，不堆边框、彩色徽标和小字号。长台词自然换行，键盘焦点、点击区域及明暗对比清晰可辨。

## 2. System A：从故事种子到精品剧本

四个主要关口是交付与选择的层级，不是只能修改四次。短片可以一次审完整剧本；长篇按集或序列分批推进，每批沿用同样的选择方式。

| 关口 | AI 自动完成 | 用户主要选择 | 控制候选成本 |
|---|---|---|---|
| A1 故事方向 | 理解种子与约束，提出有不同人物选择、冲突机制、代价的方向；必要时各写一小段样戏 | 哪个故事值得继续、哪些元素必须保留 | 默认 3 个短方案；不为未选方向生成完整剧本 |
| A2 完整故事方案 | 展开人物弧光、因果链、关键转折、结局和场次表；自动查设定冲突与伏笔回收 | 主线、关键转折、人物选择是否成立 | 1 个推荐方案；仅对有实质分歧的部分给 1–2 个替代方案 |
| A3 剧本初稿与重点精修 | 按已选方案写完整对白动作；自动通读，找节奏、人物声线、信息揭示的问题；给出修改版本 | 阅读作品；保留好段落，挑不满意的场或具体台词 | 常规场先写 1 版；关键场可比较 2 版，旧版始终可看 |
| A4 全片打磨与定稿 | 结合局部修改重新检查全片，集中给出少量影响最大的修订方案，生成交接包 | 接受哪些修订、是否定稿 | 不因一次润色重写全片；全片审查按阶段运行 |

“契约采纳→正文填充→子节点展开”的内部动作应由编排器衔接，减少逐节点操作。用户采纳一个故事方案时，界面一起展示其中新增的关键人物与事实；同批采纳后进入正式设定。内部暂定内容可以继续用于形成预览，但不得悄悄变成正式故事。

每次等待用户的应是可读成果，例如“两个结局哪一个更符合你要的余味”，而不是要求用户填写 contract、Canon ID 或处理无意义的中间确认。

### A 的精修循环

用户：“这场争吵太直白，保留最后决裂，台词含蓄一点。”

AI 自动定位场景与限制 → 读取本场完整内容、人物声线、前后场状态 → 写一个局部新版本 → 检查结局、事实与关系变化是否保持 → 展示原版/新版及关键差异。

用户可以“采用”“只保留这句”“再给一版”“保留原版”。只有改动真的改变人物目标、因果结果或已锁定内容时，才把影响范围作为新的决策交给用户。

## 3. System B：从剧本到可判断、可制作的精品分镜

本阶段 B 的主要交付应是完整分镜方案、镜头表和分镜图板。视频生成与成片装配保留为扩展模块，不应成为完成分镜必须经过的步骤。

| 关口 | AI 自动完成 | 用户主要选择 | 控制候选成本 |
|---|---|---|---|
| B1 导演方向试样 | 读懂戏剧任务与观众信息，选择代表场，做 2–3 种视听方案；包含镜头顺序及少量关键画面 | 怎么拍最符合故事气质，而非只选配色 | 先做代表场试样，选定后再展开全片 |
| B2 视觉基准与全片分镜草案 | 抽取人物/地点/道具、建议参考形象；按场生成导演方案与镜头骨架；代码补时长和约束 | 主角形象、空间、整体节奏；重点场次的处理 | 主资产成组选择；常规场 1 版、重点场按需 2 版 |
| B3 分镜图板与局部精修 | 形成可连续阅读的图板；检查人物、轴线、视线、动作衔接与信息承载；对问题镜头提出替代 | 哪个画面与镜头顺序更有表现力，保留哪些镜头 | 仅生成缺失或需要改动的画面；先用评审清晰度 |
| B4 全片复核与交付 | 连续浏览检查节奏、转场、伏笔、重复机位、可生成性；整理分镜表、图板与交接材料 | 确认完整视听叙事及最终版本 | 无改动的设计、图片、校验结果复用；必要时再做高精图 |

代表场可以选开场、主要人物冲突、关键揭示等 1–3 场，数量随作品长度调整。样本必须覆盖真实难点，不能只选容易出漂亮画面的段落。

资产、导演和镜头草案可由 AI 在同一个工作批次中自动准备；到需要用户判断视觉身份和故事表现的地方再停。B 的创作权限是改变呈现，不是自行改变故事中的原因、人物选择和结果。若发现剧本问题，形成明确修订建议供用户选择，并反馈给 A。

### B 的精修循环

用户：“这场见面不够压迫，保留第 1、4 镜和人物外貌。”

AI 保留上述镜头与人物基准 → 对第 2、3 镜设计两种有不同效果的改法 → 自动计算时长与空间连续性 → 只生成必要试样 → 用前后连看的方式展示差异。

用户采用后只更新受影响的镜头；若新版本改变转场的连接条件，再检查相邻场的边界镜头。已选画面保持可恢复，不能因为接受一场新提案而整体丢失。

## 4. 交互与 AI 自动推进

默认工作台只需要突出：当前作品、待选方案、下一步建议，以及一句话精修入口。常用动作保持稳定：采用、局部采用、再来一版、保留/锁定、恢复、继续下一步。

AI 的每个决策包应有：

- 实际可读/可看的结果。
- 与已选版本相比发生了什么变化。
- 简短说明创作效果和取舍，例如“更悬疑，但主角的主动性减弱”。
- 需要用户作出的具体选择；没有实质差异时不凑候选数。
- 必要时显示新增费用与受影响内容，默认不堆内部过程日志。

建议增加可恢复的阶段编排器：

```mermaid
flowchart LR
  A[目标与已选版本] --> B[判断下一项创作任务]
  B --> C[组装上下文与选择模型]
  C --> D[生成草案]
  D --> E[代码检查与必要的语义复核]
  E --> F[展示结果与局部差异]
  F --> G[用户选择]
  G --> H[保存版本和相关设定]
  H --> B
```

编排器以持久状态驱动，区分 `draft / checking / awaiting_choice / accepted / failed / paused`。AI 可以自动完成已选阶段内的草稿、校验、有限修复；到创作选择、重要故事变化或约定预算边界停下。

后台自动修复要有轮次和费用上限。格式错误可先用确定性规则处理；语义不满足时集中修订一次，再不满足就展示问题与候选。不要让多个评审代理互相评审并无限循环。

用户选择是质量信号。拒绝原因应区分“本次不合适”“本场要求”“整个项目偏好”，避免把一次试验永久变成全项目禁令。

## 5. 调用分配：按任务影响和难度，而非只按平台

建议先建立三个文字能力档与一个视觉档。具体模型 ID 使用可替换配置，在真实中文剧本样本上对比后决定；此报告不假设某一家当前模型一定最适合你的文风。

| 任务 | 建议配置 | 触发原则 |
|---|---|---|
| A 故事方向、人物弧光、结局与大转折 | 强创作/推理档 | 高影响关口使用，多候选集中投入 |
| A 普通场次初稿、对白精修 | 通过样本评测的主力创作档 | 默认按场生成；关键场或失败场升级 |
| A 全片结构复核 | 强档，按阶段批次运行 | 大纲选定、完整初稿、重要结构变化后 |
| 意图解析、格式整理、简单抽取 | 轻量档或代码 | 结构化明确请求直接用代码；不必每次再做模型理解 |
| B 导演方向、悬疑揭示、复杂调度 | 强档 | 重点场、高影响视听方案 |
| B 常规场导演方案、镜头骨架 | 主力档 | 场级一次输出多个镜头；单镜精修调用局部接口 |
| B 资产抽取 | 主力档，清晰结构优先代码 | 只处理新增/有变化场次，复用资产 ID |
| 镜头计数、时长、轴线、字段检查、Prompt 编译 | 代码 | 不产生 LLM 调用 |
| 人物一致性、信息是否可见、重点画面复核 | VLM / 专项检测 | 免费检查通过后、按必要性触发 |
| 图片/分镜图生成 | 图像服务 | 创意与人物基准明确后；评审图先行 |
| 调用排队、结果保存、失败分类、导出 | 普通程序 | 不需要 Agent CLI 作为常规中间层 |

格式验证和审美评判必须分开。便宜模型可以检查缺字段，但不能仅凭粗评分淘汰更有个性的作品；语义评审应给原文/镜头证据，并保留人工查看其他候选的入口。

建议的路由顺序：用户针对本次操作的选择 → 项目/场景的明确配置 → 任务类型与关键程度 → 默认档位。模型能力、上下文、结构化输出、价格、并发限制在提交前校验。

同一场景或一个创作批次尽量使用稳定的模型与风格规范。只有质量不足、能力不匹配或服务失败时切换，切换要记录，不为微小单价差在每次调用间任意漂移。

现有角色只能支持第一步：A 已有 `structure/story/script/validator/vision/intent`；B 是 `normalizer/assets/direction/vision`。B1/B3/B4 都走 `direction`，未来应拆开 treatment、scene_direction、shot_plan 等任务；仅在配置文件添加新名称不会自动生效，还要修改调用处。

## 6. 缓存需要四层，且不能妨碍“再给一版”

| 层次 | 缓存内容 | 主要收益 | 失效条件 |
|---|---|---|---|
| 业务结果复用 | 抽取、审查、已有候选、上下文摘要 | 完全避免一次重复生成/计算 | 任务输入、依赖内容、模型或提示模板变化 |
| 供应商 Prompt Cache | 重复的稳定输入前缀 | 新调用的输入处理更便宜、更快 | 具体服务的前缀、模型、有效期规则 |
| 媒体产物缓存 | 已生成的参考图、分镜图等 | 避免重复生成相同媒体 | 实际渲染输入或产物内容变化 |
| 派生计算缓存 | manifest、Prompt、连续性检查、导出 | 降低本地重复计算 | 对应输入内容或计算规则版本变化 |

三个动作必须区分：

- **继续/重新打开**：返回已有结果，不收费生成。
- **重复点击同一个提交**：绑定同一 operationId；运行中复用任务，不重复扣费。
- **再给一版**：新的 variantId 和创作意图，进行新采样；可复用稳定输入前缀，但不返回上一版冒充新创作。

文本结果键建议包含：项目作用域、任务类型、目标内容指纹、实际依赖指纹、模板/schema 版本、供应商/模型部署身份、有效参数、候选变体身份。仅对白风格改变不应让无关人物抽取缓存全部失效。跨项目复用只限明确可共享的公共模板和无项目内容的计算。

媒体键应在编译完成后由最终有效请求生成：实际 Prompt、负面 Prompt、参考图内容 SHA、模型/服务/工作流版本、尺寸、质量、seed、时长及所有影响输出的有效参数。任务名称、随机生成的数据库 ID、审核时间、锁定状态、执行 Runner 名称不应造成相同媒体重复生成。项目作用域可作为明确的隔离前缀。

seed 仅是请求参数，不是跨模型、跨版本的身份或像素一致性保证。精品角色稳定主要依赖批准的参考资产与服务能力，不能只依赖固定 seed。

需对同一个请求实现任务合并与原子占用：两个并发 cache miss 只能产生一个实际生成任务。长任务占用要能续租和恢复；超时后先核对服务端 jobId，不把“本机没收到结果”直接判成“没有生成过”。

### 稳定上下文的组织

推荐顺序：固定任务规则和 schema → 已选世界/风格基准 → 本场涉及的人物与状态 → 本场/前后边界 → 此次精修指令和差异。Prompt 顺序用显式消息/内容块表达，不依靠 JSON 字段名字猜测排序。

局部任务只带必要切片：A 的对白任务必须包含本场正文和相邻场的进入/退出状态；B 的导演任务带该场实际资产，不带全片所有资产长描述。固定角色声线卡和视觉基准按内容版本更新，避免每次重写摘要造成前缀漂移。

### 官方接口的差异

OpenAI Prompt Cache 复用输入前缀，每次仍生成新输出；缓存参数、门槛与读写价格随模型而不同。应记录缓存读取、缓存写入和普通输入，按实际接口能力适配，不能把 Responses 专有字段直接塞到任意 Chat Completions 兼容接口。[OpenAI 官方说明](https://developers.openai.com/api/docs/guides/prompt-caching)

Anthropic 支持顶层或内容块的 `cache_control`。其 `input_tokens` 不包含缓存读写，需另记 `cache_creation_input_tokens`、`cache_read_input_tokens`；不能只按 input_tokens 记总输入费用。[Anthropic 官方说明](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

Gemini 有隐式与显式缓存；显式缓存还涉及内容创建、引用与存储时长费用，需按重复使用次数判断是否划算。[Google 官方说明](https://ai.google.dev/gemini-api/docs/generate-content/caching)

因此，“打开一个 cache 开关”不足以完成缓存设计。先让本地结果复用正确，再测量供应商的实际折扣，不能把预期命中当成已节省的费用。

## 7. 单独优化场景

场景标签用于改变创作要求和检查项，不必每种题材另建一套应用或另找一个模型。

|---|---|---|---|

## 9. 费用与运行记录

每次决策批次应记录 taskType、sceneId/nodeId、operationId、variantId、routeReason、model、依赖内容版本、结果复用来源、普通/缓存输入、输出、费用、等待和生成时长、最终是否采纳。

文本费用按普通输入、缓存读取、缓存写入、输出分别乘对应单价，再加入存储和工具费用；不能把已包含的缓存 token 重复相加。缺少 usage 时标为估算/待对账，不记录为“确定为零”。

媒体费用记录到镜头和版本。A/B 各自预算独立；要做整片总成本时通过项目关联汇总，不把一个平台的金额直接当成整片花费。

推荐看板：每轮候选成本、每场被采纳结果成本、修改后保留率、关键缺陷数量、无关内容被重做的数量、本地结果复用率、供应商缓存 token 比例、图片采用率、重复提交次数、失败与未知费用。没有真实使用数据前不承诺“省 70%”等数字。

并发按服务商限制和资源类型配置。文字、图片、视频应分队列；同内容任务合并、不同场可并行、强依赖串行。不要把业务线程数简单放大当成调度优化。

## 10. 实施顺序与验收

### 第一阶段：先让迭代可靠

修正有效请求计费、缓存键、伏笔 schema、局部上下文与 A→B 交接指纹；建立稳定内容 ID 和局部 patch 采纳。先保证“我只改这部分”真的只影响应该变化的内容。

验收：只改一镜，其余镜头 ID、内容和可用媒体保持；改冻结描述产生新媒体请求；改审核备注不产生新请求；费用上限按最终发送参数计算；只改叙事信息边界也能通知 B。

同时补齐正文门禁、时序失效传播与陈旧提案保护。补充验收：Script 正文只有任意字段时应拒绝；结构合法但违反已选契约的正文要给出具体证据，不能仅因契约字段未变而放行。父节点结尾改变不应把其内部较早发生、仍满足进入条件的子场误标 broken；变化真实到达的下游场才应收到冲突。B 全片提案生成后再修改任一依赖场、资产或转场，采纳旧提案应识别实际受影响项并保留新版本；并发采纳与修改也必须在同一事务校验中得到一致结果，无关内容变动不应使整批工作作废。

### 第二阶段：让 AI 推进，人选成果

增加阶段编排、决策包、成组采纳、自然语言精修、旧版对比和恢复。A/B 默认各四个主要关口；保留高级节点/资产视图。图片生成按已选阶段预算自动准备，达到创作选择点停下。

验收：用户可以从入口走到完整剧本/分镜，不必逐节点操作 fill/expand，不必编辑 JSON；任务中断后恢复，不重复收费；用户可以保留原版、仅采纳部分改动或再给一版。

阅读与交互验收：用实际中文剧本和完整分镜图板，在桌面与约 390 px 宽的窄屏完成连续阅读和一次局部精修。正文与台词不横向溢出，调整字号后仍完整可读；B 每镜画面、台词/声音与时长可同时找到。打开候选、任务详情再返回时保留原场景和阅读锚点；后台完成不抢走阅读位置。用户能分清正式版与待选版，能看到变化并撤销，遇到失败也能继续阅读已完成作品。

### 第三阶段：让调用更聪明

接入任务级路由、动态候选数、本地结果缓存、供应商缓存用量与精确计费、任务合并和队列限流。将高成本创作集中到高影响关口，常规任务采用经评测的主力档。

验收：同一提交点击两次只有一个 provider 请求；“再给一版”确实产生新候选；读取旧版本不生成；供应商缓存命中能在账本核实；缓存失效能解释原因。

### 第四阶段：建立精品评测闭环

用少量有代表性的真实中文材料作为固定样本，例如对白、悬疑、情绪高潮、动作、群像与开场。模型方案盲评时同时看实际作品和费用，不只看模型自评分。

A 看人物主动性、因果、潜台词、伏笔、情绪和通读体验；B 看镜头是否承担信息、人物/空间是否连续、揭示是否准确、节奏、可制作性和完整图板体验。关键缺陷与主观审美分开记录。
