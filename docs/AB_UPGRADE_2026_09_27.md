# A/B 创作与制作升级 · 2026-09-27

本次已落地代码、数据协议、阅读界面和回归测试。B 保留独立的视听改编阶段：同一份 A 剧本可以生成电影、剧集、快节奏短剧拍摄版，阅读后再决定采用哪一版。真实模型创作质量和 Seedance 成片质量仍须单独试跑，本次工程验收不能代替这一项。

## 使用流程

**A 创作或小说改编 → 采用故事剧本 → 文件交接 → B 选择呈现方向 → 采用拍摄版 → 自动准备素材需求和导演分镜候选 → 选择结果 → 补齐实际参考图 → 费用预览、生成、审片。**

A 的“新建项目”保留 AI 选题卡；“小说改编”支持 TXT 和粘贴正文。长章会按段落、句末拆成阅读单元，默认每轮改编一个单元。采用后可继续下一段或局部修改。程序保存原文指纹、章节和字符区间、实际交付给模型的阅读范围；不会把上传整本书等同于模型已经读完。

B 首页按“呈现转换 → 素材 → 分镜与制作”组织。“拍摄版与历史”可以查看电影、短剧等版本；“转换 / 局部修改”生成新候选。仅切换方向、生成候选不会替换当前制作稿。旧项目使用“转换为新拍摄版”进入新流程，B 原有小说导入仍然保留。

“采用并继续”自动准备下一项需要选择的结果，后台提取和校验不再要求逐步点击。保留单步接口。任务页支持取消、恢复已停止的文字任务；付费媒体恢复需重新核对本批次费用。

画幅、故事来源、呈现方向独立选择。新项目不要求先填总时长，不固定每集分钟数；模型根据动作、对白、情绪设计镜长。没有新增累计媒体预算上限。

## 制作依据与事实保护

- A 导出 `SceneExport-v1 / schemaVersion: 3`。B 保存独立来源版本和 `shooting_script`，不回写 A 数据。
- B 可以压缩、合并、重写对白、外化解释、重分场次、调整信息呈现。每个 A 原文块必须有目标块映射和理由，删除也必须说明。
- 人物身份、关键动机、世界规则、重要因果和结果进入独立复核。涉及这些变化的 `storyChanges` 会阻止制作采用，先在 A 确认故事新版本，再重新交接。
- 分镜、事件覆盖、对白交付、素材和连续性均基于当前采用的 B 拍摄版。经过确认的 A 对白删改不会在下游被误报成漏台词。
- 局部改稿保留范围外正文、事件和分镜；采用时复核来源及基准版本，避免迟到的候选覆盖更新内容。已锁定内容不能被隐式改写。
- 新版导演稿通过修订和复核接口更新，直接保存旧接口不能绕过检查。

原创旧稿没有完整事件表时，交接会明确标为 `needs_completion`，由 B 转换阶段补全。离线演示允许结构模板用于检查操作；真实转换不能把待补全模板作为已完成连续性使用。

## 道具、状态和实际素材

事件表分别保存动作前后状态。位置、持有、包含与穿戴使用实体关系；开合、服装、伤势等使用声明字段。未知值、观众不可见、已知为空、消耗及销毁分开表达。容器移动会带着内部物品移动；封闭容器取放、异地交接、循环包含、无声明事件乱序会被程序检查。

故事发生顺序与播放顺序独立。预演、倒叙、跳时需要声明接法。预演不会提前改变正篇起态；剪辑和导出按已采用的播放顺序排列。

素材先从拍摄版提取需求，再以采用分镜筛出实际引用。身份主图记录稳定外貌与形制，变体记录临时状态。参考图有实际文件哈希、身份版本、状态、使用职责和人工观察依据。缺图只阻塞引用它的任务。起帧图使用动作起态参考，不混入动作后的参考图。

素材卡支持上传、复用已有图片，以及“费用预览 → AI 补图”。补状态图前先核对身份主图；带容纳物的状态图还会引用容纳物主图。候选图片生成后不会自动成为正式参考，需查看后采用。主图或素材文件变化后，之前的检查记录不能直接沿用。

分镜与生成单元分离，多个连续镜头可以组成一次视频任务。单元按实际配置的 `maxSeconds`、`maxImages` 和参考能力校验；没有写死 Seedance 版本或能力。当前通用直接执行器每个单元最多接一条外部强承接，更多外部承接需拆分单元。手动导入外部生成结果仍可用。

视频需记录真实文件、实际采用起止区间、实际末态及观察依据。同一生成单元可标定各镜区间，再分别审片。强承接截取采用区间的末帧，视频参考只传采用区间，装配也按该区间剪切。替换上游视频或修改采用区间会传播失效；独立关键帧和无依赖镜头保留。

## 调用与缓存

程序检查结构、引用、状态和缓存；模型负责创作与独立语义复核。每个候选最多“初稿 + 两次自动修复”，内容无进展提前停止，显示具体问题。

新增独立复核请求使用 `reviewer` 角色，默认沿用已有 `validator` 配置及单价；可在高级配置独立覆盖 `models.reviewer`。真实创作不能由演示复核模型盖章通过。电影、短剧呈现差异由模型生成并审查；离线演示不会伪装成优质改编。

已通过且输入相同的候选、章节分析、未改变的素材和审查结果优先复用。新候选随机标识持久在任务参数中，取消恢复不产生新的随机请求。媒体缓存包括实际素材文件、身份、状态、采用区间和连续依赖；费用仍使用现有调用记录、预留和本批次确认。

## 独立运行与兼容

两个应用仍有各自的数据库、配置和 Python 模块，可以分别复制运行。公共协议代码分别随两套应用交付，没有引入运行时共享依赖。

旧版交接文件继续可读。旧项目保留原流程和旧素材；进入新流程时提出拍摄版及连续性补全候选，采用后再计算实际影响。界面新建 B 项目使用 `workflowVersion: 2`；旧 API 调用未传此字段时保持旧流程兼容。v3 交接和采用新拍摄版会进入新版流程。

实施前已备份 222 个代码、数据、媒体与配置文件，并通过 SQLite 备份接口创建数据库快照，路径为根目录下 `.maintenance-backups/studio-upgrade-20260927-212333`。验收使用临时项目，没有替换用户现有项目和成片。

启动方式不变：分别运行 `system-a/start.bat`、`system-b/start.bat`。已经运行的后台需要重启，浏览器刷新后加载新版界面。本次为源码交付，没有重新打包 Windows EXE。
